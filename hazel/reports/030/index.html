Game Scripts in Hazel, Two Days In

Matthew: a report about the last 2 days -- with an idea of where we are with our goals of game scripts in hazel, for MUDU. The goal came out of his 2026-10-21 meeting with Cyrus Omar, who encouraged following the excitement: Hazel as a game script system, starting with Messed Up Dress Up (MUDU), as a general way to put Hazel code into a JS/HTML app's behavior. The two days since found some gaps in what the scripts can say, and mostly gaps in speed.

Short answers.

  1. The game's rules run in Hazel and in Fumola, beside its JS. Five rooms (the trap room, the tree houses, placed levers, the world's ways, the castle) and a 📚 Common module, written in both languages, each checked against the game's own JS: on three open pull requests to the game, behind a page-wide switch.
  2. Fumola is fast enough now; Hazel is, on trial branches. One World move at 64x64 (4,096 squares), on the same machines: Fumola with its HashMap 0.587 ms; Hazel with the game's own map 1.46 ms (2.5x). Both well inside a 60 fps frame (16.7 ms), and both flat from 3x3 to 64x64. Hazel's number needs this week's library fixes, which the library the game loads does not have, and the game holding the map. With the world passed in at every move, as the game calls its rules today, the move walks the whole world: 331 ms on the same build (Figure 1).
  3. Most of the two days went to Hazel's speed, and it paid. Functions keep their closures across the JS boundary; list loops no longer re-type the whole list each time; a big value can cross once, as a handle; values skip the evaluator's five stages (14,009 passes for count(1000) become 9,007). Together, with a map, a World move went from 241 ms to 0.97 ms (Figure 2). All on trial branches, measured on GitHub, none in the game yet.
  4. What is left for Hazel is the cost of each pass. Making the map, once a world, takes 1.5 to 2.1 s at 64x64 on GitHub's runners (2,136 ms against Fumola's 326 on the same ones): three walks of a list (two now) at Hazel's cost per evaluator pass, which pays for the editor's live features on every term (^report(29)).
  5. Next: the three-way script boxes. Each room's box a JS, Hazel or Fumola chip (the JS shown read-only, the game's own code; Hazel and Fumola to edit), a master chip, tests that keep the three equivalent, a tool for each script's overhead, and speed runs that hold each setting to a frame rate.

What was built#

  • The 🧩 Scripting panel (matthewhammer/kids-choice-games#1): one editor per room that has logic, and 📚 Common, the bodies of the modules of one Hazel program; Hazel builds the program (Hazel.runProgram) and shows it in its own tiles, in a frame, with its error marks. A rule says what to do as data (Cmd: Flip("lever_L", Done), GoSquare(c, r, side, Done)), and the game does it.
  • The rooms' rules in Hazel (matthewhammer/kids-choice-games#2): the trap room's red and blue levers, the tree houses' trap doors, placed levers and trap doors, the world's ways, the castle's pits and ladders, under ?logic=hazel, every decision checked against the JS in the game's browser checks. Its speed runs (^report(25)): levers add 0.8 to 3.6 ms, a world way about 5.6 ms on the test map, a fall or a ladder hides behind the walk, and the program compiles in about 1.2 s at load.
  • The same rules in Fumola (matthewhammer/kids-choice-games#4): wasm, a pinned build, a node check of 20,653 cases against the Hazel rules; a rule call about 1.1 to 1.4 ms against Hazel's 2.9 on one runner, and Fumola sets up in 4 ms where Hazel compiles in 514 (^report(27)).
  • The game's own map (^ticket(553), branch hazel-map-553): 📚 Common gains a balanced search tree of the world's squares (squares, square, set_square; put in order first when the game sends them in another), and 🗺️ World a rule that looks one square up (with_squares) beside the shipped one that walks the list. Checked in every run: on a world of random kinds and ways, its cells shuffled, the two agree for every square and all eight directions (392 cases).

module Common {
  // two levers flipped, one after the other
  public func flip2(a, b) { #Flip(a, #Flip(b, #Done)) };
  // the i-th of a list of Bools, false past its end
  public func nth(xs, i) { if (i < xs.size()) { xs[i] } else { false } };
  // which lever works each pit, the left and the right: normal, reversed, or at random by the game's two draws
  public func wire(mode, draws) {
    switch (mode) {
      case (#Reversed) { (#R, #L) };
      case (#Random) { if (draws.size() < 2) { (#L, #R) } else { (if (draws[0] < 0.5) { #L } else { #R }, if (draws[1] < 0.5) { #L } else { #R }) } };
      case _ { (#L, #R) }
    }
  };
  // a red lever up? (true is up)
  public func up(l, r, side) { switch (side) { case (#L) { l }; case _ { r } } };
  // each pit open: open when the lever working it is up
  public func pits_open(l, r, w) { let (w0, w1) = w; (up(l, r, w0), up(l, r, w1)) };
  // a pit that changed from was to now: SetPit, else nothing
  public func pit_moves(i, was, now, k) { if (was == now) { k } else { #SetPit(i, now, k) } };
  public func member(s, xs) { var found = false; for (x in xs.vals()) { if (x == s) { found := true } }; found };
  // a way among a square's ways
  public func has_way(d, ds) { var found = false; for (x in ds.vals()) { if (x == d) { found := true } }; found };
  // where room kind k first is in a castle's rooms, counting from 1; 0 when it is not there
  public func room_at(rs, k) { var i = 0; var at = 0; for (x in rs.vals()) { i := i + 1; if (at == 0 and x == k) { at := i } }; at };
  // the i-th room's exits, counting from 1; null past the end
  public func exit_of(xs, i) { if (i >= 1 and i <= xs.size()) { ?(xs[i - 1]) } else { null } };
  public func rooms(rs) { rs.size() };
  // the world's eight directions: each one's step across and down the map, and the way back
  public func dir(d) {
    switch (d) {
      case (#N) { (0, -1) }; case (#NE) { (1, -1) }; case (#E) { (1, 0) }; case (#SE) { (1, 1) };
      case (#S) { (0, 1) }; case (#SW) { (-1, 1) }; case (#W) { (-1, 0) }; case _ { (-1, -1) }
    }
  };
  public func opp(d) {
    switch (d) {
      case (#N) { #S }; case (#NE) { #SW }; case (#E) { #W }; case (#SE) { #NW };
      case (#S) { #N }; case (#SW) { #NE }; case (#W) { #E }; case _ { #SE }
    }
  }
}

function roomLeverFlip(side, lids = true) {
  const B = state.background;
  if (B.kind !== "castleroom") return;
  const K = castleOf(B), n = Math.max(1, Math.min(K.rooms.length, Math.round(B.castleRoom ?? 1))), key = leverKey(side, n, K.id);
  const was = trapState(B, n, K.id).open;
  B[key] = !leverDown(B, side, n, K.id);   // (ticket 307: never touched, it was down)
  changed();
  const up = !B[key], sd = side === "L" ? -1 : 1, T = trapState(B, n, K.id), now = T.open;
  turnArm(`[data-lever="${side}"] .lever-arm`, (up ? 1 : -1) * sd * LEVER_TILT, LEVER_TURN * 100 / T.speed.lever);   // (ticket 328: the room's speeds)
  if (!lids) return;
  for (const j of [0, 1]) if (now[j] !== was[j]) lidSwing(`.pit-lid[data-pit-i="${j}"]`, now[j], PIT_SWING * 100 / T.speed.lid);   // (ticket 307)
  // (Matthew: "opened by the red lever (trap door) while standing on it, and no falling sequence was triggered") a pit opened
  // under the friend: in they fall, as walking onto it does, once its lid has swung most of the way
  if (now.some((o, j) => o && !was[j])) setTimeout(fallIfOverPit, 0.6 * PIT_SWING * 100 / T.speed.lid);
}

# A red lever pulled: flip it, and each pit wired to it opens or shuts. #
# A blue lever pulled: each of its pits gets a boulder, or loses one. #
let on_event = fun (g, e) : (Globals, Event) ->
  let w = Common.wire(g.wiring, g.draws) in
  let (w0, w1) = w in
  case e
  | Pull(side) =>
    let (was0, was1) = Common.pits_open(g.lever_L, g.lever_R, w) in
    let l = if side == L then !g.lever_L else g.lever_L in
    let r = if side == R then !g.lever_R else g.lever_R in
    let (now0, now1) = Common.pits_open(l, r, w) in
    Flip(side, Common.pit_moves(0, was0, now0, Common.pit_moves(1, was1, now1, Done)))
  | PullBoulder(side) =>
    let mine0 = w0 == side && Common.nth(g.pits_on, 0) in
    let mine1 = w1 == side && Common.nth(g.pits_on, 1) in
    let lift = (mine0 && Common.nth(g.covered, 0)) || (mine1 && Common.nth(g.covered, 1)) in
    let one = fun (i, mine, k) : (Int, Bool, Cmd) -> if !mine then k else if lift then LiftBoulder(i, k) else DropBoulder(i, k) in
    one(0, mine0, one(1, mine1, Done))
  | _ => Done
  end
module TrapRoom {
  // a blue lever's pit i: nothing if not its own, else its rock lifted or a rock dropped
  func one(i, mine, lift, k) { if (not mine) { k } else if (lift) { #LiftBoulder(i, k) } else { #DropBoulder(i, k) } };
  // A red lever pulled: flip it, and each pit wired to it opens or shuts.
  // A blue lever pulled: each of its pits gets a boulder, or loses one.
  public func on_event(g, e) {
    let w = Common.wire(g.wiring, g.draws);
    let (w0, w1) = w;
    switch (e) {
      case (#Pull(side)) {
        let (was0, was1) = Common.pits_open(g.lever_L, g.lever_R, w);
        let l = if (side == #L) { not g.lever_L } else { g.lever_L };
        let r = if (side == #R) { not g.lever_R } else { g.lever_R };
        let (now0, now1) = Common.pits_open(l, r, w);
        #Flip(side, Common.pit_moves(0, was0, now0, Common.pit_moves(1, was1, now1, #Done)))
      };
      case (#PullBoulder(side)) {
        let mine0 = (w0 == side) and Common.nth(g.pits_on, 0);
        let mine1 = (w1 == side) and Common.nth(g.pits_on, 1);
        let lift = (mine0 and Common.nth(g.covered, 0)) or (mine1 and Common.nth(g.covered, 1));
        one(0, mine0, lift, one(1, mine1, lift, #Done))
      };
      case _ { #Done }
    }
  }
}

// 26-drags-and-start.js: leverPull
function leverPull(i) {
  const T0 = (state.background.things || [])[i];
  if (!T0 || T0.kind !== "lever") return;
  if (scriptEvent("Square", { tag: "PullThing", value: i })) return;   // (ticket 531: 🧩 Square's rule, when it is on)
  hzJs("PullThing", () => {
    const B = state.background, T = B.things[i], doors = [];
    // (ticket 323: a boulder lever drops a boulder into each of its trap doors as it goes over, and lifts it out as it comes back)
    for (const d of B.things.entries()) { const [j, t] = d;
      if (t.kind !== "trapdoor" || !(T.works || []).includes(t.uid)) continue;
      if (T.does === "boulder") { if (!!t.boulder !== !T.on) doors.push([j, "boulder", !T.on]); } else doors.push([j, "open", !t.open]); }
    leverPullApply(i, doors);
  });
}

// 26-drags-and-start.js: leverPullApply
function leverPullApply(i, doors) {
  const B = state.background, T = (B.things || [])[i];
  if (!T || T.kind !== "lever") return;
  T.on = !T.on;
  const swung = [], dropped = [], seed = 1 + Math.floor(Math.random() * 999999);
  for (const [j, what, v] of doors) { const d = B.things[j];
    if (!d || d.kind !== "trapdoor") continue;
    if (what === "boulder") { d.boulder = v; d.rock = T.rock || ROCK_TONES[0]; if (v) d.rockSeed = seed + j; dropped.push([j, v]); }
    else { d.open = v; swung.push([j, v]); } }
  changed();
  turnArm(`[data-drag="thing:${i}"] .lever-arm`, T.on ? LEVER_TILT : -LEVER_TILT);
  for (const [j, open] of swung) lidSwing(`[data-drag="thing:${j}"] .pit-lid`, open);   // (ticket 307)
  // (a boulder lifted out is drawn no more once it has gone: drawn again, held, for its rising; ticket 323)
  for (const [j, down] of dropped) if (down) boulderFall(`[data-drag="thing:${j}"] [data-boulder]`, true, BOULDER_FALL, boulderHits, null, boulderFalling);
  // (a placed boulder lever lifting its boulders: sparkles from the lever and from each trap door they leave)
  if (T.does === "boulder" && !T.on) { sparkleFrom(`[data-drag="thing:${i}"] .lever-arm circle`, 14); for (const [j] of dropped) sparkleFrom(`[data-drag="thing:${j}"]`, 22); }
}

let on_event = fun (g, e) : (Globals, Event) ->
  case e

  end
module Square {
  // the first thing at place i, from the j-th on
  func find(ts, j, i) { if (j == ts.size()) { null } else if (ts[j].at == i) { ?(ts[j]) } else { find(ts, j + 1, i) } };

module World {
  // Places with no way out on a side, whatever their ways say: the waterfall's N, its cliff.
  func no_way(kind, d) { kind == #Waterfall and d == #N };
  // into square (c, r), come in from back, if it has a way back; else nowhere
  func decide(x, back, c, r) { if (Common.has_way(back, x.ways) and not (no_way(x.kind, back))) { #GoSquare(c, r, back, #Done) } else { #Done } };
  func find_at(cs, i, c, r) { if (i == cs.size()) { null } else { let x = cs[i]; if (x.col == c and x.row == r) { ?x } else { find_at(cs, i + 1, c, r) } } };
  // the square a way leads to, if it is on the map: (c, r), or null
  func step(ac, ar, d, cols, rows) {
    let (dx, dy) = Common.dir(d);
    let c = ac + dx;
    let r = ar + dy;
    if (c < 0 or r < 0 or c >= cols or r >= rows) { null } else { ?(c, r) }
  };
  // A way out walked through: into the square beside it, coming in from the side facing back,
  // if that square is on the map and has a way back; else nowhere.
  public func on_event(g, e) {
    switch (e) {
      case (#Way(d)) {
        switch (step(g.at_col, g.at_row, d, g.cols, g.rows)) {
          case (?(c, r)) { switch (find_at(g.cells, 0, c, r)) { case (?x) { decide(x, Common.opp(d), c, r) }; case null { #Done } } };
          case null { #Done }
        }
      };
      case _ { #Done }
    }
  };
  // the same, the square found in the map held here
  public func way(ac, ar, cols, rows, d) {
    switch (step(ac, ar, d, cols, rows)) {
      case (?(c, r)) { switch (HashMap.get(world_held, (c, r))) { case (?x) { decide(x, Common.opp(d), c, r) }; case null { #Done } } };
      case null { #Done }
    }
  };
  // the map held here made again from the game's cells
  public func hold(cells) {
    var m = HashMap.new();
    for (x in cells.vals()) { let (m2, _) = HashMap.put(m, (x.col, x.row), x); m := m2 };
    world_held := m;
    cells.size()
  }
}

# Where room n's way out leads: 0 out of the castle, a room, or -1 nowhere. #
# out is its setting; Auto: a dungeon's ladder up to the trap room, room 1 out, any other to room 1. #
# Nowhere only where the way out is toward us (side doors, a long room's, a spiral's); elsewhere Auto. #
let way_out = fun (rooms, exits, n, out) : ([Room], [Exit], Int, Out) ->
  let ex = Common.exit_of(exits, n) in
  let toward_us = (case ex | Some(ExitSide) => true | Some(ExitLong) => true | Some(ExitSpiral) => true | _ => false end) in
  let ladder = (case ex | Some(ExitLadder) => true | _ => false end) in
  case (case out | Nowhere => (if toward_us then Nowhere else Auto) | o => o end)
  | Auto => (let t = Common.room_at(rooms, Trap) in if ladder && t > 0 && !(t == n) then t else if n == 1 then 0 else 1)
  | OutOfCastle => 0
  | Nowhere => 0 - 1
  | ToRoom(r) => if r >= 1 && r <= Common.rooms(rooms) then r else 0 - 1
  end;

let on_event = fun (g, e) : (Globals, Event) ->

  let d2 = Common.room_at(g.rooms, Dungeon2) in

module Castle {
  // Where room n's way out leads: 0 out of the castle, a room, or -1 nowhere.
  // out is its setting; Auto: a dungeon's ladder up to the trap room, room 1 out, any other to room 1.
  // Nowhere only where the way out is toward us (side doors, a long room's, a spiral's); elsewhere Auto.
  public func way_out(rooms, exits, n, out) {
    let ex = Common.exit_of(exits, n);
    let toward_us = ex == ?(#ExitSide) or ex == ?(#ExitLong) or ex == ?(#ExitSpiral);
    let v = if (out == #Nowhere and not toward_us) { #Auto } else { out };
    switch (v) {
      case (#Auto) { let t = Common.room_at(rooms, #Trap); if (ex == ?(#ExitLadder) and t > 0 and t != n) { t } else if (n == 1) { 0 } else { 1 } };
      case (#OutOfCastle) { 0 };
      case (#Nowhere) { -1 };
      case (#ToRoom(r)) { if (r >= 1 and r <= Common.rooms(rooms)) { r } else { -1 } };
      case _ { -1 }
    }
  };
  // A trap room's pit fallen into (0 the left, 1 the right):
  // the first pit drops into the dungeon, the second into the deep dungeon;
  // a castle with only one of them, both into that one.
  public func on_event(g, e) {
    let d1 = Common.room_at(g.rooms, #Dungeon1);
    let d2 = Common.room_at(g.rooms, #Dungeon2);
    switch (e) {
      case (#FallPit(i)) {
        let to = if (i == 0) { if (d1 > 0) { d1 } else { d2 } } else { if (d2 > 0) { d2 } else { d1 } };
        if (to == 0) { #Done } else { #GoRoom(to, #Done) }
      };
      case (#WayOut(n)) { #GoRoom(way_out(g.rooms, g.exits, n, g.out), #Done) };
      case _ { #Done }
    }
  }

Languages of Play#

Languages of Play: Towards semantic foundations for game interfaces (Chris Martens and Matthew A. Hammer, 2017, arXiv:1703.05410) treats what a player can say to a game as a language of its own, a player intent language, and reads a game through programming-language theory, in the slogan "games as programming languages". Its running example is a small game of moving between rooms and taking things, under five interfaces (point-and-click, bird's-eye, WASD, command line, hypertext), and its Table 1 pairs each part of a language definition with a part of a game. The game's rules, written three ways, line up with that table closely:

Where the game goes beyond the paper. The paper's languages are mathematical definitions. Here the mechanics are programs in two real languages beside the JS that defines them, held equal by tests, so one game has three semantics for the same intent language, and the 🧩 panel lets a player see and change which one runs. It also gives the paper's link to Hazelnut (an editor whose edits keep a program meaningful, cited there as the model for editing languages) a concrete place: the Hazel boxes are shown in Hazel's own tiles.

Where it does not yet. The game's interfaces (keys, the on-screen controller, clicks) are not themselves written as languages, as the paper's five are; the game's state crosses into the rules as a record of text and numbers made by its JS, not as typed terms from the start; and Hazel's sums could not yet live in the 📚 Common module, where the game's vocabulary belongs, until hazelgrove/hazel#2729 (a module's sum types usable after it), which came out of this.

Speed: what was found, and fixed#

Why a Hazel rule cost about 40 ms on a 16x16 world when the JS took 0.003 (^report(25)), why Fumola runs the same rule 2.4 to 10 times faster (^report(29)), and the fixes, each on a trial branch built by GitHub:

  • The boundary's floor (^ticket(539), branch lib-floor): a call's argument bound in the environment, not written into the call and stepped back into a value node by node.
  • Closures kept whole (^ticket(547), real branch lib-closures, ^ticket(558)): a function the library returns keeps its environment; it used to have its captured values written into its body, so a held list was evaluated again, part by part, at every call. One reference to a held list of 3,000: 77x faster. A CI test now holds it (^ticket(552): a call's evaluator passes are the same for a held list of 100 and of 10,000; without 547 the test fails).
  • List loops linear (^ticket(548)): a loop passing a growing list on pushed its type over every element each time, with a fresh id for each; building and summing 3,000 numbers, 8.9x faster.
  • Handles (^ticket(551)): Hazel.value(x) converts a JS value once; a call given the handle takes it as it is.
  • A fast path for values (^ticket(559)): with nothing probed, reused or published (the library's calls, a game's rules), a term already a value comes back at once instead of passing through the evaluator's five stages; the step count reads the same and the evaluator's tests pass unchanged. The map's set-up#

Once a world, 1,539 ms at 64x64 on the trial build, measured in parts: putting the squares in order and checking it (662), counting them (286), building the tree (927); bringing the cells over from JS is 77.7. Taking the type annotations off the map's helpers changes nothing (1,636). Each part is a walk of the list at Hazel's cost per pass, about 60 to 70 µs a square even for the count; doing the count in the same walk as the order check saved 15% (1,946 to 1,657 ms; runs 39888318843, 39890490518).

What the scripts can say#

  • Ordering strings: a map keyed by a lever's id (a string) needs strings in order. Hazel has string_compare, returning Ord (Lt, Eq, Gt), since May (Alexander Bandukwala, d5cd0a07a3, beside int_compare and float_compare). Corrected here: our ticket had said Hazel had none, from a search of one list of builtins.
  • Fumola's values from JS: JSON read straight into Fumola values (Adapton/fumola#148, merged), so a map passed in is no longer written out and parsed; and an answer more than about a thousand values deep no longer traps the wasm instance (Adapton/fumola#150, open). Fumola has no float comparison the rules can use yet (the game's draws are passed as whole millionths).
