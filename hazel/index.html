    Hazel#

    Hazel is a live functional programming environment: every edit state has a meaning, so a program has a type and a result even while it is incomplete. Hazel is developed by Cyrus Omar's group at the University of Michigan. I co-authored the first Hazel papers and its founding grants, around 2017, and since this fall I have been working on it again.

    What I'm working on#

    Livelits are GUIs for Hazel values, written as ordinary Hazel code and living inside the program they edit: a slider for a number, a color picker, a figure you pose by dragging. I'm working on user-defined livelits, ones that a Hazel programmer writes, and on making them fast enough to feel like plain apps: moving a slider should redraw a picture as quickly as it would in a small JavaScript page.

    That makes it a performance question, and most of my Hazel work right now is answering it, on two pull requests: hazelgrove/hazel#2635 (livelits with modular editors) and #2597 (the full livelits branch). The performance tracking issue is #2609.

    Livelits put a GUI inside a Hazel program. I'm also trying the other way around: Hazel inside a GUI's program, as a library its JavaScript event handlers call. That library is hazeljs (on npm): a page hands Hazel a program and JavaScript values, and gets JavaScript values back. I call a program built this way a Hazlet; the game scripts in Messed Up Dress Up are the first, and run on it. The second is a Petri net simulator: the page runs the net, and a rule written in Hazel decides what each event does. Its rules are in Hazel's own editor, on the page, so you can change them while the net runs (its source, and the report on how both apps are built).

    Games with my kids#

    The test bed is a set of small games whose features my kids, M and N, choose as they play. The first is Messed Up Dress Up, a paper doll with every part on a slider, and costumes, places and music to go with it. Each request goes live as soon as it's ready, so the next round of play tests it.

    The game is a hybrid: a JavaScript page that redraws in milliseconds, whose game logic is written as game scripts, in Hazel by default (with Fumola beside it as another point of comparison). Its toys are also rebuilt in Hazel, as user-defined livelits on the Livelit Playground, where they first took seconds. Closing that gap is what the reports measure. The games' code is on GitHub.

    More on what Dress Up is for, and every version of it kept day by day: its music, with a player, its pictures, and its reports on how fast it plays.
